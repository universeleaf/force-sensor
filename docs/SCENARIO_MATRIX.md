# EnFiRCE 场景矩阵与滑动阶段说明

本文档回答两个问题：为什么 `forces.mp4` 后半段会沿 x 方向移动，以及当前代码已经覆盖了哪些接触场景。这里的“结果”均来自仓库内已经完成的仿真输出；它们验证的是算法和数值流程，不代表真实硬件精度。

## 1. 为什么要设置滑动阶段

`out/video/forces.mp4` 的环境是顶面，法向为

```text
n = [0, 0, -1]
```

杆先沿 `+z` 方向推进，再沿平面内的 `-x` 方向移动。因为 `x` 与顶面法向正交，所以它是该场景的切向方向；沿 `x` 移动不会改变理想的法向间隙，主要激励切向摩擦。

代码在 `rod/run_rod_plane_force_sensing_experiment.m` 中显式构造了两个阶段：

1. **push**：接近平面。视频场景把初始摩擦设为 `mu=0`，先隔离法向接触和杆身形状变化。
2. **slide**：保持接触并沿切向移动。摩擦切换为 `mu=0.5`，用于检查摩擦方向、摩擦锥、粘着/滑动模式和接触力分解。

如果只有法向推进，算法可以测试“是否接触”和法向反力，却不能充分检验 Coulomb 摩擦约束。滑动阶段因此是一个诊断性实验，而不是为了让视频看起来更复杂。当前视频中向左的视觉效果来自 `x-z` 投影：世界坐标 `-x` 在绘图中就是向左。

`x` 没有普适物理意义。对任意平面，只需选择满足 `n' * t = 0` 的切向量 `t`；代码会在配置校验时把 `slideDirection` 投影到平面切空间。若要只看“向上推”，可以把视频场景的 `slideDistanceMm` 设为 0，或使用 `motionMode='push-only'`。

## 4. 类似工作的实验场景

连续体机器人力估计的实验并不只包含一个 wall。已有工作通常按“点接触、多点接触、分布载荷”和“仅形状、形状加环境几何、带时间先验”组织实验：

| 工作 | 常见场景 | 对 EnFiRCE 的直接启发 |
|---|---|---|
| [Aloi et al., IEEE RA-L 2022, DOI:10.1109/LRA.2022.3188905](https://doi.org/10.1109/LRA.2022.3188905) | 腱驱动连续体机器人上的多个三维加载位置，比较点状和高斯分布载荷 | 应加入同一观测输入下的点载荷、分布载荷和三维位置对比。 |
| [Ferguson, Rucker & Webster, IEEE T-RO 2024, DOI:10.1109/TRO.2024.3360950](https://doi.org/10.1109/TRO.2024.3360950) | 分布载荷、集中点载荷、不同稀疏传感器组合和真实腱驱机器人 | 应把环境接触力与外部点载荷分开报告，并做传感器密度消融。 |
| [Xiao & Chen, Efficient Force Estimation for Continuum Robot, 2021](https://arxiv.org/abs/2109.12469) | 单接触和多接触，使用 FBG 局部曲率，强调实时性 | 应单独报告单接触、多接触和帧耗时，不能只给离线精度。 |
| [Rucker & Webster, IROS 2011](https://ieeexplore.ieee.org/document/6094526) | 基于形状和末端位姿的点载荷概率估计 | 可作为不使用环境平面的 shape-only 点载荷基线。 |
| [Hu & Sun, Advanced Intelligent Systems 2026, DOI:10.1002/aisy.202500786](https://doi.org/10.1002/aisy.202500786) | 综述点、多个和分布接触，以及基于环境的非穿透、摩擦和准静力模型 | 说明“单 wall”只能覆盖问题的一小部分；环境信息应在多个几何和接触模式下验证。 |

## 5. 下一批场景与当前代码边界

按照上述文献和现有求解器，下一批实验应按下面顺序补齐：

1. **无接触**：杆完全在自由空间运动，统计误报接触率。
2. **末端点接触**：把杆身接触和末端点载荷分开，验证接触位置在端点附近的退化情况。
3. **倾斜和三维斜平面**：让平面法向含有 `y` 分量，避免所有实验都落在同一个 `x-z` 平面。
4. **角落/双平面**：把当前 `two-contact` 从压力测试扩展为真正的双接触逆解，输出两个接触点和两组摩擦力。
5. **圆柱或窄通道**：用多段局部平面近似曲面，并把环境观测不确定性传入 MAP。
6. **分布载荷**：增加沿弧长的 Gaussian 或分段常值载荷，与 Aloi 和 Ferguson 的报告方式一致。
7. **动态窗口**：用 `force('temporal-window')` 把相邻帧的 Cosserat 平衡和接触点运动先验联合起来，再评估滑动阶段。

目前可以直接运行的入口是：

```matlab
addpath(genpath(pwd));
force('demos');            % 六个单接触场景
force('model-mismatch');  % 双接触、曲面、摩擦失配压力测试
force('fair-baselines');  % 同一观测输入下的 shape-only/Gaussian 基线
force('temporal-window'); % 短时间窗口 MAP
```

如果只想重复某几个 GIF 场景，可以调用：

```matlab
run_contact_demo_suite({'ceiling_hook','side_wall','inclined_plane'});
```

该函数会重新写入 `out/demos/comparison.json`，完整六场景运行时间较长；提交论文前应保留运行 ID、MATLAB 版本和输入包校验值。

## 6. 对 RA-L 实验矩阵的判断

一个 wall 场景可以说明基本机制，但不足以支撑完整的 RA-L 实验。当前代码已经有单接触几何变化、摩擦滑动、噪声、多种子、深度平面和模型失配测试，足以形成仿真基线；要把结论提升为完整论文，还需要真正完成双接触/非平面逆解、分布载荷、三维斜平面和至少一种真实传感器或公开数据验证。当前结果应按这个范围表述，不能把压力测试误写成多接触已经解决。
